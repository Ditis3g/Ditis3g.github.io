앞 장에서 우리는 현실의 예외가 자동화의 경계를 넓히는 데 가장 큰 비용을 만든다는 것을 보았다. 그렇다면 자연스럽게 다음 질문이 나온다.

> 예외가 생길 때마다 사람이 규칙을 추가하는 대신, 로봇이 상황과 행동의 관계를 데이터에서 배울 수는 없을까?

이 질문은 “규칙을 모두 없애자”는 선언이 아니다. 충돌 방지, 작업 영역 제한, 속도 제한, 비상 정지처럼 반드시 명시해야 하는 조건은 여전히 남는다. 바뀌는 것은 모든 상황을 사람이 문장과 조건문으로 미리 열거하려는 방식이다. 피지컬 AI는 규칙이 담당하기 어려운 판단의 일부를 관찰 데이터와 학습된 정책으로 옮긴다.

두 방식의 차이는 “규칙이냐 AI냐”라는 이분법보다, 판단을 어디에 기록하느냐에 가깝다.

| 구분 | 규칙 기반 접근 | 데이터 기반 정책 |
| --- | --- | --- |
| 판단의 출처 | 사람이 작성한 조건과 순서 | 실제 상황에서 관찰된 상태와 행동 |
| 강점 | 예측 가능하고 검증 범위가 분명함 | 반복해서 쓰기 어려운 예외의 패턴을 흡수할 수 있음 |
| 약점 | 조건이 늘수록 충돌과 유지보수 비용이 커짐 | 학습 데이터 밖의 상황과 실패 원인을 검증해야 함 |
| 안전 설계 | 규칙·제한·인터록 중심 | 정책 + 제한 규칙 + 감시·정지 장치의 조합 |
| 적합한 영역 | 구조화된 반복 작업 | 변동이 많고 사람의 판단이 개입되는 작업 |

## 데이터는 단순한 영상 모음이 아니다

로봇에게 필요한 데이터는 “무엇을 보았는가”만으로 충분하지 않다. 같은 장면에서도 어떤 행동을 했고, 그 행동이 작업 목적에 맞았는지까지 연결되어야 한다.

| 데이터 요소 | 로봇이 배울 수 있는 질문 |
| --- | --- |
| 장면과 물체 | 무엇이 어디에 있는가? 평소와 무엇이 다른가? |
| 작업 지시 | 지금 달성해야 하는 목표는 무엇인가? |
| 행동 순서 | 어떤 순서로 손과 몸을 움직였는가? |
| 결과와 피드백 | 성공했는가? 미끄러졌는가? 다시 시도했는가? |
| 예외 상황 | 사람이 개입한 이유는 무엇인가? |

예를 들어 작업자가 눌린 상자를 집는 장면을 기록한다고 하자. 영상만 저장하면 “손이 상자 쪽으로 이동했다”는 사실은 남지만, 왜 일반적인 집기 위치를 버리고 옆면을 잡았는지는 빠진다. 반면 장면, 지시, 선택한 그립, 실패 여부, 수정 동작이 함께 기록되면 로봇은 표면의 모양과 행동의 관계를 학습할 수 있다.

이 때문에 데이터의 양만큼 중요한 것이 데이터의 구성이다. 성공 장면만 모으는 것보다 실패 직전의 상태, 사람이 개입한 순간, 다시 시도한 방법을 포함하는 편이 긴 꼬리 문제를 다루는 데 더 유용할 수 있다. 다만 학습 데이터가 많다고 해서 안전성이 자동으로 보장되는 것은 아니다. 데이터에 없는 상황을 어떻게 감지하고 멈출지, 잘못된 행동을 어떻게 제한할지는 별도의 시스템 설계 문제다.

## 모방은 출발점이고, 이해는 검증할 질문이다

사람의 시연을 보고 행동을 따라 하는 방식은 로봇에게 좋은 출발점을 제공한다. 사람이 작업을 완료하는 경로와 속도, 물체를 다루는 순서를 직접 수작업으로 코딩하지 않아도 되기 때문이다.

하지만 “따라 했다”와 “상황을 이해했다”는 같은 말이 아니다.

작업자가 상자를 오른쪽으로 옮기는 영상만 본 로봇은 그 행동을 재현할 수 있다. 그러나 오른쪽에 다른 상자가 있어 왼쪽으로 돌아야 하는 상황, 상자의 테이프가 풀려 있어 두 손으로 잡아야 하는 상황, 사람이 지나가 잠시 기다려야 하는 상황에서는 단순 복사가 부족하다. 학습된 행동은 목표와 맥락에 맞는지, 실패했을 때 회복할 수 있는지, 처음 보는 변형에도 안전하게 보수적인 선택을 하는지로 검증해야 한다.

## 피지컬 AI의 데이터 루프

현장에 배치된 로봇은 한 번 학습하고 끝나는 제품이 아니다. 새로운 예외가 발견될 때마다 기록하고, 정책을 수정하고, 다시 검증하는 루프가 필요하다.

<div class="book-flow" aria-label="피지컬 AI의 데이터 개선 루프">
  <div class="book-flow-step"><strong>현장 실행</strong><span>정상·실패·중단</span></div>
  <div class="book-flow-arrow" aria-hidden="true">→</div>
  <div class="book-flow-step"><strong>사례 선별</strong><span>왜 어려웠는가?</span></div>
  <div class="book-flow-arrow" aria-hidden="true">→</div>
  <div class="book-flow-step"><strong>정책 개선</strong><span>데이터·모델·제약</span></div>
  <div class="book-flow-arrow" aria-hidden="true">→</div>
  <div class="book-flow-step"><strong>회귀 검증</strong><span>기존 작업도 유지?</span></div>
</div>

여기서 “데이터를 모은다”는 말은 감시 카메라를 계속 저장한다는 뜻이 아니다. 어떤 사례를 학습에 넣을지, 개인정보와 작업자 안전을 어떻게 보호할지, 성공과 실패를 어떤 기준으로 라벨링할지, 업데이트 전후 성능을 어떤 테스트 세트로 비교할지를 포함한다. 피지컬 AI의 운영 역량은 모델 선택만큼이나 이 루프를 안정적으로 돌리는 능력에 달려 있다.

## 1부에서 기억할 문장

> 규칙을 없애는 것이 아니라, 규칙이 다루기 어려운 판단의 일부를 데이터 기반 정책으로 옮기는 것이다.

이제 우리는 왜 데이터와 행동 학습이 등장했는지 알게 되었다. 다음 장에서는 이 변화가 특정 연구실의 실험에 머무르지 않고, 공장·물류·서비스 현장의 자동화 경계를 어떻게 넓히는지 살펴본다.
