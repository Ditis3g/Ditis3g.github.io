언어로 “컵을 가져와”라고 말하면 사람은 준비·접근·파지·운반·놓기를 자연스럽게 나눈다. 로봇 시스템도 작업을 상태와 전환으로 표현하면 목표와 몸의 움직임 사이를 연결하기 쉬워진다. 이는 모든 행동을 딱딱한 규칙으로 고정하자는 뜻이 아니라, 현재 어디에 있고 다음에 무엇을 확인해야 하는지를 명확히 하자는 뜻이다.

## 컵 가져오기 상태 지도

```text
준비 → 대상 확인 → 접근 → 정렬 → 접촉·파지
  ↑       │          │       │          │
  └ 재관찰┴──────────┴───────┴── 실패 복구
                                      ↓
                              운반 → 놓기 → 성공 확인
```

각 상태에는 진입 조건과 종료 조건이 있다. 접근 상태는 컵이 보이고 도달 가능할 때 시작하며, 손끝이 지정 범위에 들어오거나 시야가 가려지면 다음 상태로 넘어가거나 복구한다. 성공 확인은 그리퍼가 닫혔다는 신호가 아니라 컵이 실제 목표 위치에 남았는지를 본다.

## 학습과 규칙의 경계

상태의 이름과 안전 전환은 명시적으로 두는 편이 설명하기 쉽다. 하지만 “어느 모서리를 먼저 잡을지”, “가려진 컵이 어느 위치일지”, “접촉 힘을 얼마나 조절할지”는 데이터 기반 정책이 더 유연하게 처리할 수 있다.

| 명시적으로 고정하기 좋은 것 | 학습으로 맡기기 좋은 것 |
| --- | --- |
| 비상 정지·작업 영역·최대 힘 | 물체 선택·접근 방향 |
| 성공·실패 판정의 큰 기준 | 미세한 속도·힘·자세 |
| 상태 전환의 금지 조건 | 예외 상황의 복구 후보 |

이 경계가 있으면 모델이 불확실해도 시스템 전체가 무너지지 않는다. 정책은 상태 안에서 행동을 제안하고, 상태 관리자는 결과를 확인하며, 안전층은 어떤 상태에서도 넘지 말아야 할 경계를 지킨다.

## 상태 설계는 평가 설계이기도 하다

작업을 상태로 나누면 성공률을 단계별로 볼 수 있다. 접근에서 많이 실패한다면 시야와 경로를, 접촉에서 실패한다면 그리퍼와 힘을, 놓기에서 실패한다면 성공 판정과 목표 위치를 점검할 수 있다. 이 구조는 5부의 시뮬레이션 평가에도 그대로 사용된다.
