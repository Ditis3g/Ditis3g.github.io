## 데이터 공장이라는 비유의 의미

시뮬레이션은 단순히 예쁜 가상 장면을 만드는 도구가 아니다. 한 번의 장면에서 카메라 관측, 로봇의 몸 상태, 행동, 결과를 같은 시간축으로 묶어 여러 조건으로 생산하는 공간이다.

| 현실의 병목 | 시뮬레이션이 줄일 수 있는 부담 |
| --- | --- |
| 로봇 한 대의 실제 시간 | 여러 가상 환경에서 병렬 실행 |
| 위험한 실패 | 물리 장비 손상 없이 반복 |
| 작업물 소모 | 물체 상태를 다시 생성 |
| 초기화 시간 | 즉시 시작 상태로 리셋 |
| 새 조건 비교 | 같은 정책을 여러 조건에서 평가 |

## 시뮬레이션이 자동으로 현실이 되지는 않는다

가상 환경에서 수건을 잘 접었다고 실제 수건도 같은 방식으로 접는다는 보장은 없다. 실제 천의 변형, 센서 잡음, 마찰, 케이블 흔들림, 빛의 반사처럼 모델에 넣지 않은 요소가 있기 때문이다.

따라서 시뮬레이션 데이터는 실물 검증을 없애는 자료가 아니라, 실물에서 반복하기 어려운 경험을 늘리고 위험한 후보를 먼저 걸러내는 자료다. 무엇을 가상에서 만들었고 무엇을 실제로 확인했는지 구분해야 한다.

## 물리적 경험을 다시 만드는 공간

새 로봇이나 새 카메라를 사용할 때도 시뮬레이션은 과거 행동의 의미를 새로운 몸에 맞춰 볼 수 있는 공간이 된다. 단순히 관절 숫자만 바꾸는 것이 아니라, 작업 장면과 물체 상태를 재현하고 새 몸의 궤적과 카메라 관측을 함께 생성해야 한다. 이 주제는 5부에서 자세히 다룬다.

## 시뮬레이션은 경험의 조합을 넓힌다

현실에서 수건의 위치, 조명, 카메라 시점, 마찰, 사람의 개입을 모두 바꾸며 반복하는 일은 비싸다. 시뮬레이터에서는 같은 작업의 조건을 빠르게 바꾸고, 실패한 장면을 다시 초기화하며, 실제 장비를 점유하지 않고 수많은 변형을 실행할 수 있다. 그래서 시뮬레이션은 화면을 예쁘게 만드는 도구가 아니라 물리적 경험을 생산하는 공장으로 볼 수 있다.

```text
기준 작업
  ├─ 물체 위치 변경
  ├─ 조명·카메라 변경
  ├─ 마찰·질량·접촉 변경
  ├─ 가림·장애물 추가
  └─ 실패 후 초기화·재시도
          ↓
   관측-행동-결과 데이터
```

## 가상 데이터의 의미를 현실에 맞게 유지하기

시뮬레이션에서 생성한 관측과 행동은 현실의 경험과 구조적으로 대응해야 한다. 카메라가 가상에서 물체를 왼쪽으로 보았다면 현실 카메라에서도 같은 좌표 의미를 가져야 하고, 그리퍼가 접촉했을 때의 신호가 실제 시스템에서 확인 가능해야 한다. 그렇지 않으면 데이터의 양은 늘어도 정책이 배울 수 있는 관계는 현실과 끊어진다.

| 가상에서 맞춰야 할 관계 | 현실에서 확인할 것 |
| --- | --- |
| 물체 위치와 영상 좌표 | 카메라 보정·시야·지연 |
| 관절 명령과 손끝 궤적 | 몸의 치수·조립 오차 |
| 접촉과 힘 변화 | 재질·마찰·그리퍼 상태 |
| 성공 판정 | 실제 작업 결과와 같은 기준 |

따라서 시뮬레이션 데이터는 현실 데이터를 대체하는 완제품이 아니라, 현실에서 검증할 가설을 빠르게 만드는 재료다. 5부에서는 이 대응이 깨지는 Reality Gap을 어떻게 분해하고, 어느 부분을 가상·현장·정책 중 어디에서 보완할지 다룬다.
