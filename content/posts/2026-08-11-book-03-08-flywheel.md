현장에서 성능을 만드는 과정은 한 번의 모델 학습으로 끝나지 않는다. 사람의 시범으로 출발 정책을 만들고, 실제 작업에서 실패를 발견하고, 사람이 복구한 사례를 선별해 다시 학습하고, 기존 능력이 유지되는지 확인한 뒤 다음 버전을 배포한다.

## 플라이휠의 각 단계

| 단계 | 해야 하는 질문 |
| --- | --- |
| 수집 | 어떤 관측·상태·행동을 기록했는가? |
| 학습 | 정책이 어떤 범위에서 따라 하는가? |
| 배포 | 사람 승인과 안전 중단은 어떻게 작동하는가? |
| 실패 회수 | 어떤 상태에서 어떤 복구가 필요했는가? |
| 검증 | 새 능력이 기존 작업을 망가뜨리지 않았는가? |

새 데이터가 들어왔다고 바로 모델을 업데이트하면 안 된다. 실패 원인이 센서 문제인지, 정책 문제인지, 제어 문제인지 분류해야 하고, 데이터가 잘못된 행동을 모방하게 만들지 검수해야 한다. 업데이트 뒤에는 새 사례뿐 아니라 이전에 잘 되던 작업도 다시 확인해야 한다.

## 시뮬레이션과 VLA의 위치

3부의 흐름에서 시뮬레이션과 VLA는 같은 역할을 하지 않는다. 시뮬레이션은 몸·도구·카메라·환경이 달라질 때 물리적 경험을 다시 만들고 확장하는 축이다. VLA는 물체와 지시가 달라질 때 공통 의미를 이미 배운 몸 기술과 연결하려는 축이다.

  <strong>3부의 결론</strong>
  <p>한 번의 시범은 출발점이다. 지속적인 능력은 실패를 다음 경험으로 바꾸고, 과거 경험을 새로운 조건에 맞게 옮기며, 배포 전후를 계속 검증하는 운영 고리에서 나온다.</p>

다음 4부에서는 이 가운데 VLA를 따로 떼어 본다. 언어 모델과 시각언어 모델의 출력은 어떻게 행동으로 이어지고, 행동을 숫자로 표현한다는 말은 정확히 무엇을 뜻하는가?

## 플라이휠은 데이터셋보다 운영 방식에 가깝다

학습 플라이휠을 단순히 “데이터를 모아 모델을 재학습한다”라고 쓰면 가장 중요한 선별과 검증이 사라진다. 실제 고리는 다음 질문을 반복한다.

| 단계 | 확인할 질문 |
| --- | --- |
| 시범 | 어떤 몸·센서·도구에서 수집했는가 |
| 정책 | 관측과 행동의 관계를 배웠는가 |
| 배치 | 어떤 조건에서 실패했는가 |
| 복구 | 사람이 어떤 판단으로 되돌렸는가 |
| 선별 | 다음 모델에 넣을 가치가 있는가 |
| 재학습 | 기존 능력을 잃지 않았는가 |
| 검증 | 새 조건과 기존 조건 모두에서 좋아졌는가 |

이 중 하나라도 빠지면 플라이휠은 회전하지만 능력은 늘지 않는다. 실패를 무조건 추가하면 데이터가 오염되고, 성공만 추가하면 경계 조건을 배우지 못한다. 재학습 뒤 기존 작업을 다시 시험하지 않으면 새 능력과 함께 이전 능력이 사라지는 회귀 오류를 놓친다.

## 현장 개입은 비용이면서 센서다

사람이 개입한 횟수는 운영 부담을 나타내는 지표이지만, 동시에 모델이 아직 모르는 조건을 알려 주는 센서이기도 하다. 개입 시점이 특정 조명이나 특정 물체에 집중된다면 그 조건을 별도의 평가군으로 만들 수 있다. 사람이 같은 복구 동작을 반복한다면 그 동작을 정책의 후보 행동으로 정리할 수 있다.

그러나 사람 개입이 줄었다는 사실만으로 개선을 단정할 수 없다. 사람이 포기해 버렸거나, 실패를 기록하지 않았거나, 안전을 위해 작업 범위를 좁혔을 수도 있다. 개입률은 최종 성공률·복구 성공률·작업 시간과 함께 읽어야 한다.

## 다음 단계로서의 VLA

지금까지의 플라이휠은 주로 특정 작업과 몸에 묶인 행동 경험을 다루었다. VLA는 이 경험에 언어와 시각의 의미를 연결해 “어떤 물체를”, “어떤 맥락에서”, “어떤 목표로” 다룰지의 조합을 넓히려 한다. 하지만 의미 연결이 새로운 몸놀림을 자동으로 만들어 주는 것은 아니다. 4부는 이 가능성과 한계를 함께 다룬다.
