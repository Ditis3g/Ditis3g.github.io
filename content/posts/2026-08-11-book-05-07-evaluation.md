시뮬레이션은 정책을 학습하는 장소이면서 평가 조건을 만드는 장소다. 같은 작업을 조명, 물체 위치, 마찰, 카메라 시점별로 반복하면 모델의 약한 조건을 비교할 수 있다.

## 학습 환경과 평가 환경을 나누기

학습에 사용한 장면을 그대로 평가하면 모델이 익숙한 장면을 외운 것인지, 작업 원리를 배운 것인지 구분하기 어렵다. 물체 위치·조명·배치·작업 순서를 일부 바꾼 평가 장면을 따로 두어야 한다.

| 평가 구성 | 확인할 것 |
| --- | --- |
| 익숙한 장면 | 기본 동작이 유지되는가 |
| 가까운 변형 | 위치·조명 변화에 대응하는가 |
| 새로운 조합 | 물체와 지시의 관계를 연결하는가 |
| 실패 조건 | 멈추거나 복구할 수 있는가 |
| 현실 샘플 | 가상과 다른 관측에서도 작동하는가 |

시뮬레이션의 장점은 같은 조건을 반복할 수 있다는 것이다. 모델 버전이 바뀔 때 이전 평가 조건을 다시 실행하면 업데이트로 기존 능력이 손상되었는지 확인할 수 있다.

## 평가 세트는 질문별로 나누어야 한다

하나의 평균 점수는 모델이 무엇을 잘하고 무엇을 모르는지 숨긴다. 평가 장면을 친숙한 조건, 가까운 변형, 새로운 조합, 실패·복구 조건, 현실 샘플로 나누면 능력의 종류를 분리할 수 있다. 각 세트는 학습 데이터와 겹치지 않도록 관리해야 한다.

| 평가군 | 핵심 질문 |
| --- | --- |
| 기본 재현 | 배운 작업을 다시 수행하는가 |
| 조건 변형 | 조명·위치·마찰 변화에 견디는가 |
| 의미 조합 | 새 지시와 물체 관계를 연결하는가 |
| 회복 | 실패 후 목표로 돌아오는가 |
| 현실 전이 | 가상 밖의 관측과 몸에서도 작동하는가 |

## 회귀 검증을 빼먹지 않기

새로운 실패 데이터를 넣어 한 가지 조건이 좋아졌다고 해도, 기존 작업의 성공률과 안전성이 떨어질 수 있다. 그래서 모델을 업데이트할 때는 새 평가군뿐 아니라 이전 버전이 통과했던 고정 평가군을 다시 실행해야 한다. 성능이 좋아진 부분과 손상된 부분을 함께 기록해야 다음 데이터 수집의 방향이 생긴다.

평가 결과는 숫자만 저장하지 말고 실패 장면과 원인 분류까지 연결해야 한다. 그래야 시뮬레이션이 “시험을 통과했다”는 보고서가 아니라 다음 학습과 현장 설계를 위한 관찰 장치가 된다.
