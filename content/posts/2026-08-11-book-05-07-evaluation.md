시뮬레이션은 정책을 학습하는 장소이면서 평가 조건을 만드는 장소다. 같은 작업을 조명, 물체 위치, 마찰, 카메라 시점별로 반복하면 모델의 약한 조건을 비교할 수 있다.

## 학습 환경과 평가 환경을 나누기

학습에 사용한 장면을 그대로 평가하면 모델이 익숙한 장면을 외운 것인지, 작업 원리를 배운 것인지 구분하기 어렵다. 물체 위치·조명·배치·작업 순서를 일부 바꾼 평가 장면을 따로 두어야 한다.

| 평가 구성 | 확인할 것 |
| --- | --- |
| 익숙한 장면 | 기본 동작이 유지되는가 |
| 가까운 변형 | 위치·조명 변화에 대응하는가 |
| 새로운 조합 | 물체와 지시의 관계를 연결하는가 |
| 실패 조건 | 멈추거나 복구할 수 있는가 |
| 현실 샘플 | 가상과 다른 관측에서도 작동하는가 |

시뮬레이션의 장점은 같은 조건을 반복할 수 있다는 것이다. 모델 버전이 바뀔 때 이전 평가 조건을 다시 실행하면 업데이트로 기존 능력이 손상되었는지 확인할 수 있다.

## 평가 세트는 질문별로 나누어야 한다

하나의 평균 점수는 모델이 무엇을 잘하고 무엇을 모르는지 숨긴다. 평가 장면을 친숙한 조건, 가까운 변형, 새로운 조합, 실패·복구 조건, 현실 샘플로 나누면 능력의 종류를 분리할 수 있다. 각 세트는 학습 데이터와 겹치지 않도록 관리해야 한다.

| 평가군 | 핵심 질문 |
| --- | --- |
| 기본 재현 | 배운 작업을 다시 수행하는가 |
| 조건 변형 | 조명·위치·마찰 변화에 견디는가 |
| 의미 조합 | 새 지시와 물체 관계를 연결하는가 |
| 회복 | 실패 후 목표로 돌아오는가 |
| 현실 전이 | 가상 밖의 관측과 몸에서도 작동하는가 |

## 회귀 검증을 빼먹지 않기

새로운 실패 데이터를 넣어 한 가지 조건이 좋아졌다고 해도, 기존 작업의 성공률과 안전성이 떨어질 수 있다. 그래서 모델을 업데이트할 때는 새 평가군뿐 아니라 이전 버전이 통과했던 고정 평가군을 다시 실행해야 한다. 성능이 좋아진 부분과 손상된 부분을 함께 기록해야 다음 데이터 수집의 방향이 생긴다.

평가 결과는 숫자만 저장하지 말고 실패 장면과 원인 분류까지 연결해야 한다. 그래야 시뮬레이션이 “시험을 통과했다”는 보고서가 아니라 다음 학습과 현장 설계를 위한 관찰 장치가 된다.

## 함께 읽는 보충 내용 — 성공률만으로 부족한 이유

짧은 작업에서 성공률이 높아도 긴 작업에서는 실패가 누적된다. 한 단계의 성공률이 95%이고 20단계가 이어진다면, 각 단계가 독립적이라는 단순 가정 아래 모든 단계를 성공할 확률은 약 36%다.

이 계산은 실제 시스템의 성능을 그대로 예측하는 공식이 아니라, 긴 작업에서 중간 실패를 함께 봐야 한다는 직관을 위한 예시다.

| 지표 | 묻는 질문 |
| --- | --- |
| 작업 성공률 | 목표를 최종 달성했는가? |
| 단계별 성공률 | 어느 단계에서 실패하는가? |
| 완료 시간 | 성공까지 얼마나 걸리는가? |
| 사람 개입률 | 몇 번 도움을 요청했는가? |
| 복구 성공률 | 실패 뒤 작업을 이어 갔는가? |
| 중단 안전성 | 위험할 때 제대로 멈췄는가? |

좋은 평가는 평균 성공률을 높이는 것뿐 아니라 어떤 조건에서 실패하는지 드러내야 한다. 그래야 시뮬레이션과 현장 데이터가 다음 학습으로 연결된다.

## 긴 작업에서는 성공이 곱해진다

한 작업이 여러 단계로 이어질 때 각 단계의 작은 실패가 누적된다. 20단계가 있고 각 단계의 성공률이 95%라면, 단계가 독립적이라는 단순 가정에서 전체 성공 확률은 약 36%가 된다. 실제 시스템에서는 단계 간 의존성과 복구가 있으므로 정확한 예측은 아니지만, 긴 작업을 최종 성공률 하나로 평가해서는 안 된다는 직관을 준다.

따라서 어느 단계에서 실패가 집중되는지와 실패 뒤 작업을 이어 갈 수 있는지를 함께 보아야 한다. 한 단계의 성공률이 낮아도 빠른 복구가 가능할 수 있고, 평균 성공률이 높아도 한 번 실패하면 위험한 상태로 남는 작업일 수 있다.

## 운영 지표를 함께 읽기

현장에서는 성공률이 높지만 사람이 매번 물체를 다시 배치해야 하는 시스템보다, 성공률이 조금 낮아도 스스로 복구하고 사람 개입이 적은 시스템이 더 유용할 수 있다. 시간당 완료 수, 재시도 횟수, 사람 승인과 복구 시간, 장비 점유, 중단 후 재시작 가능성까지 운영 지표에 포함해야 한다.

지표는 서로 충돌할 수 있다. 속도를 높이면 완료 시간은 좋아지지만 충돌과 파손이 늘 수 있고, 보수적으로 멈추면 안전성은 좋아지지만 처리량이 떨어진다. 피지컬 AI 평가는 단일 순위를 정하는 일이 아니라 작업의 우선순위를 수치로 드러내는 일이다.
