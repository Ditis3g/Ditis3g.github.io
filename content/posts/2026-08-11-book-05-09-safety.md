모델의 확신도는 안전 보증서가 아니다. 확실한 성공처럼 보이는 예측도 센서 오류나 학습 분포 밖의 장면에서는 틀릴 수 있다. 현실 시스템은 불확실성을 감지했을 때 행동을 줄이거나, 다시 관찰하거나, 사람에게 넘기거나, 멈출 수 있어야 한다.

## 안전한 실패의 조건

| 상황 | 위험한 반응 | 더 안전한 반응 |
| --- | --- | --- |
| 물체를 확실히 보지 못함 | 추정 위치로 계속 접근 | 다시 보기·정지 |
| 사람의 손이 들어옴 | 원래 궤적을 유지 | 속도 감소·대기 |
| 접촉 힘이 예상보다 큼 | 계속 밀어붙임 | 힘 제한·후퇴 |
| 모델 출력이 급격히 변함 | 새 행동을 즉시 실행 | 출력 제한·사람 확인 |

안전층은 모델의 판단을 대신해 모든 작업을 수행하는 층이 아니다. 허용하지 않을 행동과 반드시 멈춰야 할 상태를 명확히 만들어 모델의 유연성을 현실의 경계 안에 둔다.

가상 환경에서도 같은 원칙으로 안전 조건을 시험할 수 있지만, 실제 사람과 장비를 대체하는 검증은 아니다. 현실의 안전 절차와 가상 테스트를 함께 운영해야 한다.

## 불확실성은 숫자 하나로 표현되지 않는다

모델이 내놓는 확률이나 확신도는 행동 후보를 비교하는 데 도움이 될 수 있지만, 센서가 고장 났거나 학습 범위 밖의 장면이라는 사실을 자동으로 보장하지는 않는다. 시야가 가려졌는지, 관측이 오래되었는지, 여러 센서가 서로 모순되는지, 정책의 출력이 갑자기 흔들리는지 같은 시스템 신호를 함께 봐야 한다.

| 불확실성의 신호 | 보수적 대응 |
| --- | --- |
| 영상 가림·노출 급변 | 속도 감소·시점 변경·재관찰 |
| 센서 간 불일치 | 실행 보류·상태 확인 |
| 오래된 관측 | 행동 청크 폐기·새 입력 요청 |
| 정책 출력 급변 | 출력 제한·사람 승인 |
| 접촉 힘의 예상 밖 변화 | 후퇴·그리퍼 해제·중단 |

## 안전한 실패는 설계된 행동이다

멈추는 것만으로 충분하지 않을 때가 있다. 로봇이 물체를 든 채 멈추면 물체가 떨어질 수 있고, 통로를 막은 채 정지하면 사람이 위험해질 수 있다. 안전 상태는 작업과 몸에 따라 달라지며, 감속·후퇴·그리퍼 유지·물체 내려놓기·사람 호출 중 하나로 구체화해야 한다.

이때 안전층은 모델의 목표를 완전히 무시하지 않는다. 목표를 유지하되 허용된 범위에서 가장 낮은 위험의 행동을 선택하게 한다. 안전과 유용성을 함께 설계해야 현장이 비상 정지를 남발하지 않으면서도 위험을 통제할 수 있다.

## 가상 검증과 현실 절차의 연결

시뮬레이션에서는 사람의 접근, 센서 끊김, 관절 제한, 충돌 후보를 반복해 시험할 수 있다. 하지만 실제 사람의 움직임과 장비의 고장 양상은 가상과 다를 수 있다. 가상에서 통과한 안전 조건은 현실의 제한된 영역에서 감독 하에 다시 검증하고, 그 결과를 실제 운영 절차와 교육에 반영해야 한다.

## 함께 읽는 보충 내용 — 현장은 끝이 아니라 학습의 시작이다

가상에서 현실로 옮겼다고 프로젝트가 끝나는 것은 아니다. 실제 현장에는 모델이 보지 못한 물체, 조명, 작업 순서, 사람의 개입이 계속 나타난다. 배치는 마지막 시험이 아니라 다음 학습 루프의 시작이다.

## 현장 도입의 순서

1. **작업 범위 정의**: 어떤 물체·위치·속도·사람 동선을 허용할지 정한다.
2. **사람 감독으로 시작**: 모델이 자신 있게 행동하지 못하거나 안전 경계에 접근하면 사람이 승인하거나 중단한다.
3. **실패 분류**: 인식·정책·제어·환경·안전 중 어느 층의 문제인지 기록한다.
4. **작은 업데이트**: 새 사례를 반영하되 기존 작업을 다시 시험한다.
5. **범위 확장**: 검증된 조건에서만 물체·위치·작업의 범위를 넓힌다.

| 현장 질문 | 확인할 것 |
| --- | --- |
| 얼마나 자주 성공하는가? | 최종 성공과 단계별 실패 |
| 사람은 얼마나 개입하는가? | 승인·복구·원격 도움의 빈도 |
| 위험하면 멈추는가? | 중단 동작과 재시작 절차 |
| 실패가 개선으로 이어지는가? | 로그 선별·학습·회귀 검증 |
| 다른 조건으로 확장 가능한가? | 새 몸·카메라·물체에서의 전이 |

5부의 결론은 “시뮬레이션이 현실을 대신한다”가 아니다. 가상 환경은 경험을 만들고 변형하며 시험하는 강력한 공간이지만, 현실의 차이는 배치 이후에도 계속 드러난다. 피지컬 AI의 완성도는 한 번의 전이 성공보다, 현실에서 발견한 차이를 다시 데이터·환경·정책·안전 설계에 반영하는 속도와 품질로 판단해야 한다.

> **가상에서 현실로 옮기는 일은 도착이 아니라, 학습 루프가 실제 세계와 연결되는 순간이다.**

## 현장 배치는 단계적으로 넓혀야 한다

처음부터 사람과 물체가 뒤섞인 전체 현장에 투입하기보다, 작업 범위와 속도, 물체 종류, 사람 감독의 수준을 단계적으로 넓히는 편이 안전하다. 각 단계의 통과 조건은 성공률 하나가 아니라 실패를 감지하고 중단하며 복구할 수 있는지까지 포함해야 한다.

| 단계 | 허용 범위 | 다음 단계로 가기 위한 확인 |
| --- | --- | --- |
| 관찰 | 로봇은 보고 기록만 함 | 센서·로그·상태 추정의 신뢰성 |
| 제한 실행 | 정해진 물체·속도·공간 | 성공·중단·사람 개입 기록 |
| 감독 실행 | 변형 조건과 사람 감독 | 복구와 회귀 검증 |
| 부분 자율 | 승인 빈도 축소 | 운영 지표와 안전 경계 |
| 범위 확장 | 새 물체·위치·작업 | 새 조건별 재검증 |

## 현장 로그는 다음 버전의 설계 문서다

성공과 실패의 영상만 저장하는 것으로는 부족하다. 어떤 모델 버전과 환경 설정을 사용했는지, 센서가 정상인지, 사람이 언제 개입했는지, 왜 중단했는지, 작업을 어떻게 복구했는지 함께 기록해야 한다. 그래야 같은 장면을 재현하고 개선의 효과를 비교할 수 있다.

현장 학습의 속도는 재학습 횟수가 아니라 좋은 사례가 고리 전체를 통과하는 속도로 결정된다. 로그를 선별하고, 원인을 분류하고, 가상과 실물에서 재현하고, 새 정책을 검증하고, 기존 능력의 회귀를 확인하는 흐름이 빠르고 정확해야 한다.

## 5부를 마치며

Sim-to-Real은 가상 세계에서 현실 세계로 지식을 복사하는 단순한 수송 문제가 아니다. 현실의 중요한 조건을 가상에 반영하고, 통제 가능한 변동은 현장 설계로 줄이고, 남은 차이는 강건한 정책과 안전한 운영으로 감당하며, 실제 실패를 다시 가상과 학습으로 돌려보내는 반복 설계다. 이 고리가 작동할 때 시뮬레이션은 현실의 대체물이 아니라 현실을 더 빠르고 안전하게 이해하는 실험 공간이 된다.
