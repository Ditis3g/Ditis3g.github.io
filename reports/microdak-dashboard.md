# 마이크로닥 대시보드 업데이트

공개 페이지: https://ditis3g.github.io/microdak/

메뉴는 그래프 탐색(50)과 소개(60) 사이의 마이크로닥(55)입니다. 기존 Hugo / Stack / GitHub Pages 게시 방식을 유지합니다.

## 구매 실적 입력

`data/microdak.json`의 `parts`에서 품목 ID를 찾아 값을 수정합니다. `main`에 반영하면 기존 GitHub Actions가 자동 게시합니다. 저장소 수정 권한이 필요합니다.

- `received_qty`: 실제 확보 수량. 미확인은 `null`, 확인 결과 없으면 `0`. `qty`와 같은 단위입니다. 충족 여부와 부족 수량은 자동 계산됩니다.
- `actual_krw`: 해당 항목의 실제 지출 누적 원화 금액. 미입력은 `null`, 확인된 무지출은 `0`. 분할 결제는 합산하고 환불은 차감한 순액을 입력합니다.
- `actual_final`: 비용 정산이 끝났을 때만 `true`. 이때 `actual_krw`는 숫자여야 합니다. 정산 완료 항목만 초과·절감 차액에 포함합니다.
- `order_status`: `unrecorded`(미입력), `planned`(미발주), `ordered`(발주·배송 중), `received`(입고 기록).
- `purchase_note`: 구매처·구매일·배송 등 공개 가능한 메모. 개인정보·주문번호는 넣지 않습니다.
- `updated`: 항목 갱신일, 예: `2026-09-20`. 최상위 `updated`도 함께 갱신합니다.

입력 예시(실제 구매 기록 아님): 서보 15개 중 5개가 도착했고 132,000원을 냈지만 추가 구매가 남았다면 `received_qty: 5`, `actual_krw: 132000`, `actual_final: false`입니다. 화면에는 10개 부족, 실제 지출 132,000원, 정산 차액 대기로 나타납니다.

`null`과 `0`을 구분합니다. 구매 여부를 모르는 상태를 0원·미보유로 바꾸지 마세요. 배송·세금과 재제작 예비비는 `kind: "reserve"`이며 수량 집계에서 제외됩니다.

## 예산과 집계

기준 예산 `estimate_krw`, 단가 `unit_krw`, 범위 `low_krw`·`high_krw`를 실제 가격으로 덮어쓰지 않으면 원래 예산과 비교할 수 있습니다.

- 준비 소계: 23항목 중 가격 기입 22개 2,768,260원 + IMU 구매비 미정. 개발·예비비 제외 초기 구매 소계 2,468,260원 + IMU 구매비.
- 누적 지출: 입력된 `actual_krw`의 합. 모두 `null`이면 미입력으로 표시합니다.
- 예산 잔액: 기준 준비예산 − 누적 지출. 향후 결제 의무나 최종 예상비용과는 다릅니다.
- 정산 차액: 정산 완료 항목의 실제 지출 − **같은 항목들의** 기준 예산. 양수 초과, 음수 절감.
- HAT는 **3장 전체 구매비** 1,250,700원입니다. 416,900원은 장당 배분액이며 단독 주문 단가가 아닙니다.
- IMU는 **완제품 1개 구매**입니다. 미정 가격 4개 필드는 모두 null로 두며 소계 제외·견적 대기로 표시합니다. 전용 제조 1,080,000원은 현행 예산 제외입니다.
- HAT VAT는 A03에 포함됩니다. 실제 항목별 지출에 이미 포함한 VAT·배송을 C01에 중복 입력하지 않습니다.
- 확보 수량은 초기 구매 단위 기준이며 실물 동작·검사 합격을 뜻하지 않습니다.

## 개발·시험 갱신

`hardware`, `software`의 `state`는 `done`, `progress`, `blocked`, `pending`입니다. 카드에 명시한 작업 범위의 상태이며 프로젝트 전체 완성률이 아닙니다. 완료 증거를 `detail`, 다음 작업을 `next`에 남깁니다.

`tests`의 `state`는 `passed`, `issue`, `pending`, `running`, `failed`입니다. `environment`는 `PC` 또는 `실물`입니다. 실제 결과 `result`, 기준과 한계 `criteria`, 화면 상태 `status`를 갱신합니다. 실물 통과 KPI는 실물 항목 중 `passed` 개수로 자동 계산됩니다. 별도의 PC 요약 문구는 9월 14일 검토 기록입니다.

최근 이력은 `history`, 기준 자료는 `sources`입니다. 견적 변경 시 `quotes`, `price_date`, 해당 항목 예산과 `history`를 함께 갱신합니다.

## 2026-09-14 디자인 갱신

마이크로닥 자체 CAD 도면을 바탕으로 만든 AI 이미지를 상단에 배치했습니다. 노란색 표지, 아이콘 메뉴, 둥근 상태 카드로 바꾸고 자재 23개 항목과 견적 상세 메모는 기본적으로 접어 두었습니다. 목록을 펼치면 기존 수량·실지출·정산 비교를 그대로 볼 수 있습니다. 이미지는 실물 제작 완료 사진이 아닙니다.

이미지 원본과 생성 프롬프트는 `reports/microdak-image.md`에 기록했습니다. Hugo가 480px·900px WebP를 만들어 화면 크기에 맞게 사용합니다. 예산·구매·개발 데이터와 계산 기준은 변경하지 않았습니다.

## 네 가지 요약과 잔여 예상비 (2026-09-14)

첫 화면은 해야 할 일, 사야 할 것, 이미 쓴 비용, 앞으로 쓸 예산으로 구성합니다. 상세 사양·개발·테스트·견적·기록은 접힌 폴더에 유지합니다. 구매 부품군은 purchase_groups로 정의하며 자재 21개를 중복 없이 묶습니다.

parts.remaining_krw에 해당 품목에 앞으로 지출할 예상 금액을 입력할 수 있습니다. null이면 max(기준 예산 − 입력된 지출, 0)을 잠정값으로 사용합니다. 정산 완료(actual_final=true) 항목은 잔여 0원이며 양수 잔여액을 함께 기록할 수 없습니다. 추가 구매가 있다면 정산을 다시 열고 잔여액을 입력합니다.

가격 미정 항목은 준비·잔여 소계에서 제외하고 별도 표시합니다. 2026-09-16 모터 구매 반영 후 잔여 소계는 2,372,260원 + IMU 구매비 미정입니다. 보유품으로 추가 지출이 없다면 actual_krw=0, actual_final=true로 정산하거나 remaining_krw=0을 입력합니다. 잔여 예상은 구매 의무나 확정 견적이 아닙니다.

## 추가 장비 지출 (2026-09-15)

기존 제작 견적에 없던 구매는 additional_expenses에 기록합니다. actual_krw는 누적 실제 지출에 합산되며 첫 화면에 품명과 금액을 표시합니다. 기존 제작 예산·잔여 지출 예상·제작 품목 정산 차액에는 영향을 주지 않습니다. updated는 기록 갱신일이며 구매일을 의미하지 않습니다.

뱀부랩 X2D Combo 3D 프린터 1,349,000원은 운영자가 제공한 제품명과 금액으로 기록했습니다.

## 진행률 (2026-09-15)

운영자 최신 보고를 우선 반영합니다. hardware 7단계, software 3단계의 state=done 개수를 전체 단계 수로 나눠 반올림합니다. 현재 HW 3/7=43%, SW 2/3=67%, 전체 5/10=50%입니다. 진행 중 단계에 임의 부분 점수를 부여하지 않으며 작업 시간·난이도 가중치는 사용하지 않습니다. MuJoCo 이식 100%는 운영자가 확인한 개별 성과이며 전체 SW 또는 실물 보행 완료를 뜻하지 않습니다.

사야 할 것 요약은 current_purchase_plan에 기록한 최신 모터·라즈베리파이 계획을 사용합니다. 이전 견적의 Radxa 가격은 새 라즈베리파이 가격으로 전용하지 않고 상세와 예산 기준 메모에 남깁니다. 다른 자재의 보유 수량·실제 비용은 추정하지 않습니다.

## IMU 완제품 구매 전환 (2026-09-15)

A04를 완제품 1개 구매로 변경하고 기존 제작 예상 1,080,000원을 제외했습니다. 구매 방식 결정은 모듈 구매·통합 완료로 계산하지 않으며 진행률은 HW 3/7, SW 2/3, 전체 5/10을 유지합니다. 과거 전용 보드 PC 검토는 참고 기록으로 분리했습니다.

D01 100,000원은 통합 검증 소모품 예비액, D02 200,000원은 HAT·배선/기구 수정 예비액으로 유지했습니다. 전용 MCU 평가보드·디버거 구매 전제와 IMU PCB 재제작은 제외했습니다. 호스트 통합 인건비는 별도입니다.

`unit_krw`, `estimate_krw`, `low_krw`, `high_krw`는 가격 미정일 때 모두 `null`이어야 합니다. 견적 수령 시 네 필드를 함께 채웁니다. `remaining_krw=null`이고 예산도 미정이면 잔여 소계에 포함하지 않으며 미정 항목으로 표시합니다. 실지출 입력은 가격 미정과 무관하게 누적됩니다. 미정 예산 항목은 정산 차액 비교에서 제외합니다.

메인 컴퓨터 모델이 미정이므로 J7 후보는 핀·OS·I²C 검증 과제로 남겼습니다. 완제품 구매만으로 기존 ID 200 의존이 해소되는 것은 아니며 드라이버·런타임 수정·축/지연/고장 대응 시험이 필요합니다.

## 모터 구매 실적 (2026-09-16 확인)

XL330-M288-T 15개 총 396,000원(개당 26,400원) 구매 완료·배송 대기. A01 실지출 396,000원, 정산 완료, 입고 0개를 기록했습니다. 모터를 추가 구매 목록에서 제외하고 입고 확인 단계로 전환했습니다. 실제 구매일·배송 예정일은 입력되지 않았습니다.

기준 준비 소계 2,768,260원 유지. 잔여 예산 소계 2,372,260원 + IMU 구매비 미정, 프린터 포함 누적 지출 1,745,000원입니다. 현행 사양서는 v0.7(2026-09-16)입니다.

## 결제 완료 항목 집계 (2026-09-16)

이미 쓴 비용 카드의 결제 완료는 자재·예비비와 별도 장비 지출 전체에서 actual_final=true인 항목 수입니다. 추가 장비에도 actual_final을 명시합니다. 프린터와 모터 결제가 완료되어 2 / 24개 항목으로 표시합니다. 배송·입고 상태와는 별개입니다.

예산이 있는 결제 완료 항목만 정산 차액 비교에 포함합니다. 예산이 없는 장비 지출은 결제 완료 건수와 누적 지출에 포함하되 예산 초과액으로 계산하지 않습니다.


## 2026-09-16 J7 구성과 구매 항목 분리

메인 컴퓨터는 Radxa ZERO 3W로 확정했습니다. current_purchase_plan에 라즈베리파이를 넣지 않습니다. HW는 모터 구매·입고와 메인 컴퓨터 구매·준비를 분리하여 8단계, SW는 3단계입니다. 완료 단계 수는 유지되므로 전체 진행률은 5/11=45%로 계산됩니다. 분모 변경에 따른 수치이며 완료 작업 취소가 아닙니다.

전장 도면은 /microdak/wiring/ 전체 화면 및 /posts/microdak-wiring-j7/ 블로그 글에 게시합니다. IMU 제조사·모델명은 비기재, J7 연결 경로만 확정합니다. 다른 개발자의 기립·보행 성공은 사용자 전달 보고로 표시하며 자체 실물 합격 건수에 합산하지 않습니다.


## 2026-09-16 · 시뮬레이션 영상 소개

작업실 상단에 microdak_mujoco 원본 37초 영상을 배치했다. “한 걸음씩, 현실을 향해.”와 “곧 실물 마이크로닥으로 만나요.”로 현재 시뮬레이션 연습과 앞으로의 실물 제작을 소개한다. 데스크톱은 문구·영상 병렬, 모바일은 세로 배치다. 영상은 원래 화면비·전체 길이·오디오를 유지한 H.264/AAC 웹용 MP4(약 3.1MB)이며, 12초 프레임을 포스터로 사용한다. 기본 무음·자동 재생, 기본 플레이어 조작 및 전체 화면을 지원한다. 배선도 링크는 현황 카드 아래로 이동했다. 구매 금액·진행 단계·실물 시험 결과는 변경하지 않았다.


## 2026-09-16 · 컬러 작업실 시안 적용

사용자가 승인한 미리보기 시안을 운영 페이지에 적용했다. 상단 메뉴, 큰 제목과 영상, 노랑·민트·코랄 제작 과정 카드, 라벤더·살구·하늘색 작업·예산 카드로 구성한다. 영상의 무음 자동 재생 및 모바일 배치를 유지한다. 기존 데이터에서 구매 금액·진행률을 그대로 계산하며 상세 자료의 펼치기와 배선도 링크도 유지한다.
