# 마이크로닥 대시보드 업데이트

공개 페이지: https://ditis3g.github.io/microdak/

메뉴는 그래프 탐색(50)과 소개(60) 사이의 마이크로닥(55)입니다. 기존 Hugo / Stack / GitHub Pages 게시 방식을 유지합니다.

## 구매 실적 입력

`data/microdak.json`의 `parts`에서 품목 ID를 찾아 값을 수정합니다. `main`에 반영하면 기존 GitHub Actions가 자동 게시합니다. 저장소 수정 권한이 필요합니다.

- `received_qty`: 실제 확보 수량. 미확인은 `null`, 확인 결과 없으면 `0`. `qty`와 같은 단위입니다. 충족 여부와 부족 수량은 자동 계산됩니다.
- `actual_krw`: 해당 항목의 실제 지출 누적 원화 금액. 미입력은 `null`, 확인된 무지출은 `0`. 분할 결제는 합산하고 환불은 차감한 순액을 입력합니다.
- `actual_final`: 비용 정산이 끝났을 때만 `true`. 이때 `actual_krw`는 숫자여야 합니다. 정산 완료 항목만 초과·절감 차액에 포함합니다.
- `order_status`: `unrecorded`(미입력), `planned`(미발주), `ordered`(발주·배송 중), `received`(입고 기록).
- `purchase_note`: 구매처·구매일·배송 등 공개 가능한 메모. 개인정보·주문번호는 넣지 않습니다.
- `updated`: 항목 갱신일, 예: `2026-09-20`. 최상위 `updated`도 함께 갱신합니다.

입력 예시(실제 구매 기록 아님): 서보 15개 중 5개가 도착했고 132,000원을 냈지만 추가 구매가 남았다면 `received_qty: 5`, `actual_krw: 132000`, `actual_final: false`입니다. 화면에는 10개 부족, 실제 지출 132,000원, 정산 차액 대기로 나타납니다.

`null`과 `0`을 구분합니다. 구매 여부를 모르는 상태를 0원·미보유로 바꾸지 마세요. 배송·세금과 재제작 예비비는 `kind: "reserve"`이며 수량 집계에서 제외됩니다.

## 예산과 집계

기준 예산 `estimate_krw`, 단가 `unit_krw`, 범위 `low_krw`·`high_krw`를 실제 가격으로 덮어쓰지 않으면 원래 예산과 비교할 수 있습니다.

- 기준 준비예산: 전체 23항목 3,848,260원. 개발·예비비를 뺀 초기 구매 예산: 3,548,260원.
- 누적 지출: 입력된 `actual_krw`의 합. 모두 `null`이면 미입력으로 표시합니다.
- 예산 잔액: 기준 준비예산 − 누적 지출. 향후 결제 의무나 최종 예상비용과는 다릅니다.
- 정산 차액: 정산 완료 항목의 실제 지출 − **같은 항목들의** 기준 예산. 양수 초과, 음수 절감.
- HAT는 **3장 전체 구매비** 1,250,700원입니다. 416,900원은 장당 배분액이며 단독 주문 단가가 아닙니다.
- IMU는 **1로트** 1,080,000원입니다. 부품 10EA와 완성 양품 납품 수량은 다릅니다. 확정 전 10장으로 바꾸지 않습니다.
- HAT VAT는 A03에 포함됩니다. 실제 항목별 지출에 이미 포함한 VAT·배송을 C01에 중복 입력하지 않습니다.
- 확보 수량은 초기 구매 단위 기준이며 실물 동작·검사 합격을 뜻하지 않습니다.

## 개발·시험 갱신

`hardware`, `software`의 `state`는 `done`, `progress`, `blocked`, `pending`입니다. 카드에 명시한 작업 범위의 상태이며 프로젝트 전체 완성률이 아닙니다. 완료 증거를 `detail`, 다음 작업을 `next`에 남깁니다.

`tests`의 `state`는 `passed`, `issue`, `pending`, `running`, `failed`입니다. `environment`는 `PC` 또는 `실물`입니다. 실제 결과 `result`, 기준과 한계 `criteria`, 화면 상태 `status`를 갱신합니다. 실물 통과 KPI는 실물 항목 중 `passed` 개수로 자동 계산됩니다. 별도의 PC 요약 문구는 9월 14일 검토 기록입니다.

최근 이력은 `history`, 기준 자료는 `sources`입니다. 견적 변경 시 `quotes`, `price_date`, 해당 항목 예산과 `history`를 함께 갱신합니다.

## 기준 자료와 검증

제작사양서 본문 v0.5(2026-09-11), 예상견적(2026-09-11), Fanduck IMU 검토(2026-09-14)를 요약했습니다. 사양서 파일명 v0.1/v0.2는 참조 경로 유지를 위한 이름입니다. 내부 제작 파일·견적서 원본·연락처·로컬 경로는 공개 저장소에 복제하지 않습니다.

`node scripts/validate-microdak.cjs`로 데이터 형식·비용·수량을 검사한 뒤 기존 Hugo 0.163.3 Extended로 `hugo --gc --minify`를 실행합니다. 대시보드는 Hugo가 HTML로 렌더링하므로 JavaScript 없이도 요약·표·접기·메뉴가 동작합니다.
## 2026-09-14 디자인 갱신

마이크로닥 자체 CAD 도면을 바탕으로 만든 AI 이미지를 상단에 배치했습니다. 노란색 표지, 아이콘 메뉴, 둥근 상태 카드로 바꾸고 자재 23개 항목과 견적 상세 메모는 기본적으로 접어 두었습니다. 목록을 펼치면 기존 수량·실지출·정산 비교를 그대로 볼 수 있습니다. 이미지는 실물 제작 완료 사진이 아닙니다.

이미지 원본과 생성 프롬프트는 `reports/microdak-image.md`에 기록했습니다. Hugo가 480px·900px WebP를 만들어 화면 크기에 맞게 사용합니다. 예산·구매·개발 데이터와 계산 기준은 변경하지 않았습니다.

## 네 가지 요약과 잔여 예상비 (2026-09-14)

첫 화면은 해야 할 일, 사야 할 것, 이미 쓴 비용, 앞으로 쓸 예산으로 구성합니다. 상세 사양·개발·테스트·견적·기록은 접힌 폴더에 유지합니다. 구매 부품군은 purchase_groups로 정의하며 자재 21개를 중복 없이 묶습니다.

parts.remaining_krw에 해당 품목에 앞으로 지출할 예상 금액을 입력할 수 있습니다. null이면 max(기준 예산 − 입력된 지출, 0)을 잠정값으로 사용합니다. 정산 완료(actual_final=true) 항목은 잔여 0원이며 양수 잔여액을 함께 기록할 수 없습니다. 추가 구매가 있다면 정산을 다시 열고 잔여액을 입력합니다.

구매 실적이 모두 미입력인 초기 화면은 전체 계획 3,848,260원을 표시하며 기보유·기지출 반영 전임을 명시합니다. 보유품으로 추가 지출이 없다면 actual_krw=0, actual_final=true로 정산하거나 remaining_krw=0을 입력합니다. 잔여 예상은 구매 의무나 확정 견적이 아닙니다.
