## 기능 접근성 보완 (0.33)

사진 관련 기능이 상단 `…` 안에 섞여 있고 사진 우클릭은 연결되지 않았던 문제를 보완했습니다. 사진을 기준으로 메뉴를 구성하고, 다중 선택/압축/편집 이력에 따라 실행 가능 여부와 이유를 표시합니다. 단순 명령 목록 존재가 아니라 실제 메뉴 이벤트로 사진 선택·회전·되돌리기와 편집 화면 전환을 검사합니다. 파일 조작은 기존 확인 절차와 원본 보호 원칙을 유지합니다.

## HDR 원본 표시 (0.32~0.33)

Bandisoft의 HDR 형식·비디오 출력 요구와 Microsoft의 scRGB 출력 정의를 바탕으로, 기존 SDR 편집과 분리한 HDR 원본 보기를 추가했습니다. 원본과 표시 조절값을 분리하고 사용할 수 없는 화면/그래픽 장치는 이유와 함께 SDR로 대체합니다.

Academy Software Foundation의 공개 OpenEXR 사진 5종과 독립 합성 입력을 사용해 부동소수점 보존·색 좌표·투명도 축소를 검사합니다. XYZ 원색의 0 y 좌표와 AP0의 음수 y 좌표, 색 좌표 백색과 명시적 중립색의 차이를 구분합니다. 숨김 렌더 검사를 물리 HDR 화면 계측으로 대체하지 않습니다. 지원 범위와 한도는 [HDR 안내](HDR.md), 정확한 실행 결과는 [검증 기록](TESTING.md)에 남깁니다.

0.33은 Alliance for Open Media의 libavif 공개 PQ 사진과 별도 인코더로 만든 AVIF/HEVC 입력을 사용해 PQ 절대 밝기·HLG 기준 밝기, 전체/제한 범위, 색공간 변환을 검사합니다. AVIF/HEIF의 모든 게인맵·파생 이미지·ICC 조합을 지원한다고 확대 해석하지 않습니다.

## 모니터 색상 관리 (0.31)

Bandisoft의 [ICC 도움말](https://kr.bandisoft.com/bandiview/help/icc-profile/)에 있는 표시 모드와 모니터 갱신 요구를 분리해 구현합니다. Windows의 [Advanced Color/ICC 동작](https://learn.microsoft.com/en-us/windows/win32/wcs/advanced-color-icc-profiles)에 따라 기본 프로필이 없으면 sRGB로 표시하고, 운영체제 설정이나 프로필 연결을 변경하지 않습니다.

표시 전용 변환과 sRGB 저장 경로를 분리했으며, 색 변환을 끈 상태에서 원래 Adobe RGB 값을 sRGB로 잘못 표기해 내보내던 오류를 수정했습니다. 단일·다중·분할 저장, 인쇄·동영상·AI PNG에 같은 원칙을 적용합니다. 기능 범위와 미완료 항목은 [색상 관리 안내](COLOR.md), 시험 결과는 [검증 기록](TESTING.md)에 명시합니다.

## ALZ·EGG 읽기 (0.30)

- 압축 안의 사진을 읽는 경로에 ALZ와 EGG를 연결합니다. 기본 열기·목록·일괄 변환은 공통 확장자 목록을 사용하며, 압축 컨테이너를 수정하거나 모든 파일을 디스크로 추출하지 않습니다.
- ALZ의 CP949/UTF-8 파일명 및 암호와 데이터 서술자 확인 바이트, EGG의 암호별 검증자·암호문 HMAC·출력 CRC를 구분합니다. HMAC가 없는 구형 AES/LEA 파일은 길이·CRC 검사에 의존하므로 같은 인증 강도를 갖는다고 설명하지 않습니다.
- 분할 ALZ는 명시된 분할 꼬리표와 이어지는 볼륨 번호를, 분할 EGG는 같은 폴더의 파일 ID와 양방향 연결을 확인합니다. EGG의 중간 조각을 선택해도 첫 조각으로 거슬러 올라갑니다. 누락·중복 ID·순환·다른 폴더/보조 연결 파일은 실패 처리합니다.
- 한 번의 열기에서 여러 EGG 조각을 선택하면 동일 묶음의 사진을 중복 추가하지 않습니다. 사용자가 처음 선택한 원본 경로는 유지합니다. 별도 요청·즐겨찾기·이웃 이동 전체의 동일 묶음 통합은 남아 있습니다.
- 솔리드 EGG는 하나의 압축 스트림을 순서대로 읽습니다. 파일별 출력 구간과 압축 블록별 CRC 구간을 별도로 계산하며, 선택 사진 이후를 포함한 필요한 무결성 검사도 수행합니다. 큰 솔리드 앨범은 일반 압축보다 느릴 수 있습니다.
- 읽기 작업의 기존 45초/768MiB 격리를 사용합니다. 일반 사진을 열 때 추가 압축 라이브러리나 새 상주 서비스가 필요하지 않습니다. 압축 조각은 요청이 끝나면 닫고, 부분 출력은 실패 시 확정하지 않습니다.
- 구현 참고자료는 alkegi의 MIT 코드 및 CC0 형식 관찰 자료입니다. 공식 UnEGG 모듈은 사용하거나 배포하지 않습니다. 실제 제작 프로그램 전반·모든 변형·NAS/이동식 드라이브·암호화 파일명은 아직 완료가 아닙니다.

## 추가 압축 형식 (0.29)

Bandisoft의 [에디션별 비교표](https://www.bandisoft.com/bandiview/help/edition-comparison/)에서 요구 형식을 재확인하고, Igor Pavlov의 [공식 7-Zip 26.05](https://www.7-zip.org/download.html) 읽기 라이브러리를 별도 작업에 연결했습니다. 1,908,736바이트의 DLL과 동일 버전 소스·고지를 함께 보관하며 다른 제품의 UI/코드는 복제하지 않습니다.

- 공통 입력 목록에 CAB/LZH/LHA/ISO/UDF를 추가하여 열기·드롭·실행 옵션·이웃 위치·변환 대상 선택에 반영합니다. 기존 ZIP/RAR/7Z 경로를 교체하지 않습니다.
- 한 번에 하나의 별도 작업에서 지정 파일을 읽고, 요청마다 입력 핸들을 닫습니다. 사진 데이터는 제한된 크기의 메모리/비공개 스트림으로만 전달하며 압축 항목 이름을 디스크 쓰기 경로로 사용하지 않습니다. 분할 파일의 외부 경로·링크를 자동으로 열지 않습니다.
- 요청 45초·별도 작업 768MiB·자식 생성 금지·누적 CPU 제한·100,000항목·512MiB 사진·1GiB 입력/솔리드 읽기를 적용합니다. 작업 재사용은 최대 128요청 또는 누적 CPU 45초 이전까지만 하며 유휴 약 15~30초 뒤 종료합니다. 이는 자원 제한/실패 격리이며 운영체제의 완전한 보안 샌드박스는 아닙니다.
- 공개 libarchive 표본은 출처와 해시를 기록해 실제 CAB/LHA 압축 해제를 검사하는 데 사용하며 앱에 포함하지 않습니다. 사진 표시/변환은 별도의 자체 생성 PNG와 Windows 생성 CAB/디스크 이미지로 검사합니다.
- 공식 라이브러리에서도 열지 못하는 LHA 헤더 레벨 3은 구체적인 미지원 안내를 표시합니다. 분할·특수 파일명 인코딩·나머지 압축 형식과 HDR 등 전체 대응 목표를 축소하지 않습니다.

## 실행 옵션과 변환창 (0.28)

Bandisoft의 [명령행 도움말](https://www.bandisoft.com/bandiview/help/command-line-parameter/)을 다시 확인해 실행 명령·입력·보기·창 옵션을 연결했습니다. 별칭과 한도는 [실행 옵션 안내](LAUNCH.md)에 명시합니다.

- 옵션을 검증한 뒤 요청한 사진을 처음 선택하며, 실행 중의 보기 방향·슬라이드쇼 간격은 평소 설정을 덮어쓰지 않습니다. 목록 번호와 TIFF 내부 페이지는 구분합니다. 잘못된 옵션은 이유와 도움말로 안내합니다.
- 명령 파일은 UTF-8 인자 목록으로만 읽습니다. 외부 명령·스크립트 실행이 아니며, 포함 반복·길이·따옴표·인자 수를 검사합니다. LNK는 저장 대상만 읽고 대상 프로그램이나 바로가기의 인자를 실행하지 않습니다.
- 표준 입력은 파이프/파일일 때만 읽고 고유 파일명으로 원래 바이트를 보관합니다. 이미지 검증과 SVG 외부 참조/스크립트 차단을 재사용합니다. 입력 취소·대기 중인 파이프·원래 핸들 보존·실패 임시 파일 정리를 검사했습니다.
- 독립 변환 명령은 명시한 사진/폴더만 목록에 넣고 메인 뷰어의 디코딩·선택에 의존하지 않습니다. 빈 변환창에도 파일/폴더 추가·목록 확인/제거·중복 방지·작업 취소가 있습니다. 원본 파일이나 메인 편집을 바꾸지 않으며 별도의 내보내기 확인이 필요합니다.
- 소스 준비 중 다른 사진을 열거나 취소하면 늦은 결과를 적용하지 않습니다. 100% 다음 사진의 원해상도 읽기, 빈 변환창의 불필요한 옵션 정리, 열린 대화상자의 테마 대비를 함께 보완했습니다.
- 실제 보조 모니터·혼합 DPI·자동 실행 등록·단일 인스턴스 메시지 전달·모든 RAW의 표준 입력 자동 판별은 완료로 취급하지 않습니다. 이번 변경으로 형식/HDR/영상/CAD의 남은 기능이 해결된 것은 아닙니다.

## 기본 스티커와 새 설명만 공통 저장 (0.27)

근거는 이스트소프트의 [알씨 9.0 사용 설명서](https://aldn.altools.co.kr/altools/manual/alsee_90_manual.pdf) 91쪽입니다. 기본 스티커 선택/더블클릭·사용자 도장 가져오기·사진에 적용·여러 사진 적용을 독립적으로 구현했습니다. 동일한 디자인 목록이나 자산을 복제한 것이 아니라 이 프로젝트용으로 새로 제작한 12종을 제공합니다.

- 스티커 선택 화면의 한국어/영어 검색과 분류, 비어 있는 결과, 투명 배경 큰 미리보기, 키보드/더블클릭 선택을 제공합니다. 기본 PNG는 최대 256px, 합계 665,981바이트이며 이 화면을 열 때만 순차 준비합니다. 모든 파일의 SHA-256·치수·8bit RGBA·메타데이터 없음·투명 픽셀 RGB 정리를 검사했습니다.
- 새 설명 편집창의 ‘여러 사진에 저장’에서 이번 객체 하나만 각 사진의 마지막 구도에 추가합니다. 배경 사진의 다른 도장·글자·구도·보정·액자를 복제하거나 지우지 않습니다. 출력으로만 적용하며 메인 화면의 편집 기록과 원본은 유지하고 초안 편집창도 닫지 않습니다.
- 여러 장을 선택했다면 선택, 한 장이라면 현재 목록 전체를 기본으로 하며 저장 전에 변경할 수 있습니다. 창을 여는 시점의 대상/편집/초안을 사용합니다. 위치/크기는 비율이며 각 사진의 색 보정은 새 객체에도 적용됩니다. 사진 정보 문구는 사진별 동적 템플릿이 아닙니다.
- 기존 객체는 추가 당시 좌표에서 재편집하기 때문에 이 경로에서는 공통 복사를 노출하지 않습니다. 새 설명의 최종 구도 좌표와 섞지 않으며, 일반 F3의 공통 설명 항목은 시작 방법을 안내하는 비활성 상태입니다.
- 모든 스티커가 버전 5 자산으로 중복 제거되어 저장되고 다시 열었을 때 출력 픽셀이 동일한지 검사했습니다. 액자 병용은 기존 버전 6을 사용하며 전체 4MiB/64자산 제한은 그대로입니다. 객체 순서 변경·복제, 고해상도/벡터 스티커, 실제 터치/고배율 DPI 조작 검증은 남아 있습니다.
